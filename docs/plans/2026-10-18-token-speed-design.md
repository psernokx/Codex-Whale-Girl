# Token 速率与项目整理设计

用户要求：保留已超分素材和可用项目，清理重复文件，同步 GitHub，参考开源项目显示当前输入/输出 Token 速率。

采用现有本地 rollout 增量读取，不修改 Codex，不增加日志服务器或遥测收集。参考 Token Pulse 的响应边界与累计计数差分，以及 Codex Speed Monitor 对生成/工具耗时的区分；独立实现，不复制第三方代码。另两种方案为可见文字估算和配置遥测代理：前者无法正确统计输入/推理，后者增加配置与数据面，当前均不采用。

输入数字为每次请求报告的输入 Token（含缓存）除以整个响应区间，称输入吞吐估算；输出优先使用助手 item 的开始时间到 usage 记录，缺失时使用请求边界，最后回退累计计数间隔。它们都不是精确 prefill 或逐 token 流式测量。非缓存输入与推理 Token 在详情中解释，输入和输出不会使用互不相干的计数/时间区间。

现有用量牌增加紧凑的输入/输出速率文本；详情展示区间、口径、计数和采样时间。无记录、过期和 Codex 已退出各有明确状态。只展示当前选择监控的会话，不将不同会话、不同响应的速率相加。

共享 Node/Electron 代码用于三端。测试覆盖重复 usage、首次样本、计数重置、时间倒序、工具时间排除、缓存与推理不重复计数、记录过期、当前会话选择及退出。

大体积高清资源单独作为 GitHub Release 资源包发布，源码中保存校验清单与下载恢复脚本；CI 先恢复资源再测试/构建。保留作者描述和许可证。
