# Windows 高清素材回接 macOS（1.10.0）

## 来源

输入为用户提供的 `WhaleGirl-1.9.9-4x60-Windows-MotionFix.zip`（3,240,359,943 字节）。外层 ZIP 的全部文件通过 CRC 校验，内层 NSIS 7z 中 app.asar 提取校验通过。安装资源包尾部有附加数据提示；应用资源本体成功校验。本机未运行 Windows EXE。

从 Windows 应用资源中接入：

- `assets/dsh-pet-4x60/` 和独立清单：16 组，6,558 帧，1648×1376；运动片段 frameMs=1000/60，单帧 dragging_dizzy 保留原时长。
- `assets/action-library/`：106 个 2560×1440 / 60 FPS 透明 WebM、海报和来源清单。
- 动作搜索/分类目录，六个常用动作优先使用高清版本。
- 应用内动态开关优先于系统减少动态设置，用户关闭动态后使用静态海报。

Codex 监控、进程发现、用量读取及 frame-player 的时间轴实现与原项目一致。保留本地 package.json、依赖锁文件及三端打包配置，未用 Windows 包内裁剪过的 package.json 覆盖开发项目。

## 本机补全

安装包未包含 actions.json 引用的作者说明，从先前固定提交的交接包补回全部 106 份原文至 `assets/action-library/author-descriptions/`。动作按钮悬浮说明提供原作者动作概述；作者原文和来源提交保留。

修复关闭动态后手动点选全库动作仍播放视频的问题，改为显示该动作海报。测试初始化等待实际 UI 就绪，避免大资源加载时固定 500ms 等待造成误报。

## 验证边界

资产报告保存在 `artifacts/windows-motionfix-import/mac-asset-verification.json`：核对全部帧尺寸/透明格式/清单时长、106 个视频 SHA256/帧包数/分辨率/帧率，并对解码 Alpha 做抽查。

运行时报告为 `artifacts/darwin-runtime-audit.json`：记录 requestAnimationFrame 间隔、观察到的解码图像变化和进程资源占用，不代表物理屏幕扫描输出的精确帧率。测试机器同期运行其他图形程序，不是独占硬件性能基准。

Windows 安装包未附生成脚本、模型哈希或 GPU 处理报告。动作清单仍注明循环视觉审查待完成，不能将所有素材视为已完成无缝循环验收。当前仅提供手动点播目录和已有六个常用待机入口，没有自动将所有动作随机映射到 Codex 状态。

高清二进制约 3 GB，暂未推送到 GitHub；后续分发应使用独立资源包或发布附件，避免直接写入 Git 历史。旧素材仍保留在本地项目与 Git 历史以便回退。

## macOS 播放优化与实测

逐帧播放器改为串行异步解码：下一帧准备好后才替换画面，负载过高时按原时间轴跳过过期帧；动作切换会使旧解码结果失效。关闭桌宠窗口后台节流，保留最多两张解码缓存。不会通过延长动画来伪装高帧率。

本机源码动画冒烟测试（含模拟系统减少动态、手动关闭动态、106 项目录）及连续播放审计通过。当前机器负载下，三个 20 秒场景的解码画面更新约为 7.45、7.30、7.70 次/秒，未准备好画面的观察比例为 0；60 FPS 素材未达到稳定 60 FPS 呈现。详细数据见运行时报告，不能将测试通过理解为流畅度达标。

37 项原有自动测试通过，另增加并通过 1 项慢解码回归测试，验证解码串行、积压帧跳过及切换动作后旧解码不能覆盖新画面。

## 本机安装结果

新版应用资源已安装至 `/Applications/小鲸鱼看板娘.app`，版本 1.10.0。保留原来的 Electron 43.4.1 运行程序，更新 app.asar 与版本信息；重新签名的独立测试副本曾遇到系统加载拦截，未作为正式安装。旧版完整应用备份在 `artifacts/windows-motionfix-import/小鲸鱼看板娘-1.9.9-backup.app`。

安装版首次动画测试出现一次气泡坐标不匹配（416 vs 284），第二次完整运行通过，包含动作目录、六个常用动作、动态开关与气泡定位。首次启动布局是否存在时序问题仍需留意，不能因复测通过断言从未出现问题。源码与安装包核心代码逐字节一致；106 个目录视频齐全。

## 1.10.1 连续播放优化

- 从原始 4x 帧生成 15 段 1024×856 / 60 FPS 透明 VP9 播放副本；单帧片段仍用静态图。对应最大 150% 桌宠在 2x 显示器上约 1014 像素的显示宽度，原始 1648×1376 帧完整保留。
- 浏览器连续解码，播放速率固定为 1；保持原片段的帧数、时长、循环/单次语义。同一工作片段之间切换不重置进度。视频失败时回退逐帧播放，旧动作的异步完成事件不能覆盖新动作。
- `scripts/build-runtime-videos.py` 记录构建过程，逐片核对帧包数、时长、尺寸与解码透明通道；报告在 `artifacts/runtime-video-build.json`。
- 气泡同时监听文字容器、人物容器、文档与视口大小变化，在下一帧重算位置；覆盖人物与用量独立缩放。
- 39 项单元测试通过。源码完整动画测试及三组 20 秒性能检查通过，视频提交帧率约 55.98、54.17、56.42 FPS，画面未就绪比例 0。测量使用 requestVideoFrameCallback，非物理屏幕扫描测量；负载变化会影响结果。
- 原始 2560×1440 动作库以荡秋千抽测约 56.85 FPS，未为 106 个动作逐一做性能基准。动作库保留原始视频。
- 共享 Electron 播放代码适用于三端，但本次运行实测仅覆盖 macOS。

1.10.1 安装版验收：`packaged: true`，三组视频提交帧率分别约 55.03、55.67、54.97 FPS，未就绪比例均为 0，切换后恢复工作状态通过。完整安装版动画测试退出码 0。已重新以正常模式启动 `/Applications/小鲸鱼看板娘.app`；旧 1.10.0 资源备份为 `artifacts/windows-motionfix-import/app-1.10.0.asar`。

## 1.10.2 交互检查与修复

进一步检查发现：

1. 初始化期间的工作状态/独立缩放事件可能早于页面监听器注册，旧安装版 Codex 冒烟测试可复现仍显示休息。增加 renderer-ready 握手：界面配置加载完后，主进程重发最近状态和实际缩放值；测试刻意提前发送状态验证启动同步。
2. 摸头动画约 4.03 秒，但原恢复计时为 2.2 秒；第 3 秒检查已切回工作，可复现截断。现在通过非循环视频/逐帧播放器的结束回调恢复工作，超时仅用于资源加载失败兜底。交互中切换动态开关也重新安排恢复逻辑。
3. 拖动的点击抑制仅从按住开始计算，长拖结束时可能已过期。改为松手后再抑制 500ms，避免拖动结束额外触发摸头；增加回归测试。

40 项单元测试通过；Codex 初始化、原有菜单、用量、对话与动画集成检查通过。交互检查记录位于 `artifacts/interaction-audit.json`，包括第 3 秒仍播放摸头、结束后恢复工作、快速切换不会被旧动作覆盖。原生鼠标长按拖动不等同于状态模拟测试，需单独区分测试边界。

1.10.2 安装版复测：核心源码与 app.asar 内容逐字节一致；Codex 集成检查和动画/交互检查均退出码 0，覆盖互动中重新开启动画不沿用旧的 2.2 秒静态计时。正常模式已重新启动。源码三组连续播放实测约 57.62、56.77、55.43 FPS，未就绪比例 0；本轮没有重复安装版性能基准。
