# 小鲸鱼桌宠：RTX 5080 透明动画补帧任务书

## 给执行代理的目标

把 Codex-Whale-Girl 的 16 组高清透明动画从约 23.81 FPS 补到 60 FPS，保留动作速度、人物大小、透明背景、循环行为和 Codex 状态映射。先做工作、思考、拖动三个预览，再全量处理。交付能实际运行的补帧脚本、模型版本记录、素材、对比页、验证报告和三端兼容的播放器更新。

这是一份交接任务，不代表已经补帧。当前正式版本仍为 1.9.7、42ms/帧。仓库已提供时间轴规划器和结构检查器，**尚未提供 RIFE RGBA 推理适配器**；执行代理需要实现并验证它，不要把规划文件当成已生成的动画。

## Windows / RTX 5080 环境

1. 使用普通用户权限，独立 Python 3.11 虚拟环境。确认 NVIDIA 驱动正常，`nvidia-smi` 能识别 RTX 5080。
2. 按 PyTorch 官方安装页选择支持 Blackwell 的 CUDA 构建。CUDA 12.8 及更高版本的相关构建支持 Blackwell；当前新版本应优先核对 CUDA 13.x 安装项和驱动要求。不要安装不支持 sm_120 的旧 CUDA 构建，也不要把“cuda.is_available() 为真”当成计算已验证。
3. 可从下面命令开始；若官方安装矩阵变化，按官方页面调整并记录版本：

```powershell
git clone --branch codex-desktop https://github.com/psernokx/Codex-Whale-Girl.git
cd Codex-Whale-Girl
py -3.11 -m venv .venv-interpolation
.\.venv-interpolation\Scripts\python.exe -m pip install --upgrade pip
.\.venv-interpolation\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130
.\.venv-interpolation\Scripts\python.exe -m pip install numpy Pillow opencv-python tqdm
.\.venv-interpolation\Scripts\python.exe -c "import torch; assert torch.cuda.is_available(); print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0), torch.cuda.get_device_capability(0)); x=torch.randn(512,512,device='cuda'); y=x@x; torch.cuda.synchronize(); print(y.mean().item())"
```

4. 下载官方 Practical-RIFE，优先评估上游推荐的 4.25 动画模型；权重及配套 Python 文件都从官方 README 的模型入口获取。记录仓库提交、模型 SHA256、Python/PyTorch/CUDA/驱动版本。模型目录留在 `tools-local/`，不要加入 Git 或安装包。
5. 若标准模型在眼睛/手指处有伪影，可用另一官方模型做同段对比。先 FP32 验证，再测 FP16；不要默认认为更高模型版本或更低精度效果更好。

官方来源：
- https://github.com/hzwer/Practical-RIFE （模型、代码及许可）
- https://github.com/nihui/rife-ncnn-vulkan （可选 Vulkan 后端；自行验证透明通道支持）

## 时间轴：保持原速度，不做重复帧伪装

```powershell
.\.venv-interpolation\Scripts\python.exe scripts/frame-rate-job.py plan --fps 60 --out artifacts/frame-rate-60
```

得到 `timeline.json`、`expected-manifest.json`、`summary.csv`。时间轴已经规定每个目标帧取哪两张源图，以及真实的插值位置 t。

- 目标采样时刻为 k×1000/60 ms；原时刻为 i×42 ms。
- 输出清单使用 1000/60 ms，逐组总时长误差小于一帧（16.667ms）。不能把 42ms 改成 16.667ms 后仍播放原来的 2,600 帧。
- 原坐标正好落在整数帧时保留源图；静止内容可复用，不强造运动。运动段不能用帧复制、帧混合或简单淡入淡出来假装 AI 补帧。
- loop=true 时，最后一张到第一张也按时间轴处理；loop=false 时保持末姿势，不得跨到另一动画。
- `dragging_dizzy` 只有一张，保留一张与原时长；不要为静态素材复制无意义的帧。
- 预计共 6,558 帧。单组数量和时长以生成的 summary.csv 为准。
- 30 FPS 可作为低负载备选，使用 `--fps 30` 另行生成计划，不要混用两个计划的清单。

## 透明通道：必须处理的重点

普通 MP4 无法作为本项目透明素材的交付格式。不要直接用 RGB 补帧工具输出后抠黑底，也不要把相邻 Alpha 简单平均，这会产生双边、拖影和黑边。

优先方案：从所选 RIFE 模型的实际代码取得同一目标时刻的双向运动场及遮挡/融合权重；使用与 RGB 相同的坐标约定、填充与裁切，把原两帧的 Alpha 同步变形并合成。处理预乘 Alpha 时避免透明区域 RGB 污染，Alpha=0 处不要做不稳定的除法。模型接口可能随版本改变，必须阅读所选模型代码再写适配器，不要假设所有版本都暴露同一个 flow/mask API。

若采用黑/白双背景重建等替代方案，必须专门验证两次推理的运动场差异；不能默认两次 RGB 推理结果可直接相减得到可靠 Alpha。透明边缘不合格时停止全量替换，保留当前正式素材并报告问题。

实现脚本应：
- 按 timeline.json 而不是固定“×2 后改 FPS”执行任意时刻插值。
- 先校验源清单及每个源帧 SHA256。
- 支持指定 clips、断点续跑、失败重试和耗时统计；断点必须绑定模型、输入哈希、参数，不能误用另一版本旧输出。
- 输入只读，输出到 `artifacts/frame-rate-60/output/assets/dsh-pet/`。
- 暂存透明 PNG 便于排查，最终输出 824×688 RGBA WebP；编码质量先沿用 95。
- 输出完整 manifest；`frameInterpolation.status` 设为 `complete`，记录真实 modelSha256、模型版本和源清单哈希。不要把 planned 清单直接标记为完成。

## 先做三段，再全量

1. 从 working、thinking、dragging 各取约 2 秒，生成原帧率/60 FPS 同步对比页面，支持暂停、逐帧和黑/白/灰背景。
2. 检查工具图标、眼睛、头发、手指、裙边、透明孔洞；不得出现双影、拉丝、肢体变形或透明轮廓不同步。
3. 测量这三段推理时间、编码时间、显存峰值，再按实际数量估算全量耗时。不要编造 5080 性能数据。
4. 样片合格后执行全部 16 组；不通过就保留正式素材，给出失败片段。

## 播放器适配（同样必须交付）

当前 `setInterval` 是按回调次数推进。改成以 `requestAnimationFrame` 时间戳为依据，根据经过时间选择帧；发生短暂卡顿时跳过过期帧，不能把整段动作拖慢。

- stop/切换动作要取消旧回调、旧异步加载和 onEnd，避免旧动作回写。
- 共享动画的 Codex 工作状态切换仍保持当前位置。
- 非循环动画只触发一次结束回调；待机吃 Token 后正确返回 idle。
- 使用有限的预解码缓存，例如最多 12 帧约 27 MB 原始像素，别一次解码全部 6,558 帧。实测并记录缓存与内存，不必拘泥于 12。
- `petStatePoster` 现在硬编码源序号 120/60，补帧后必须改按 posterTimeMs 选择代表图，否则“工作中很多工具”的图会错。expected-manifest 已提供 posterTimeMs。
- 更新冒烟测试中 `_121.webp`/`_061.webp` 等旧文件名假设，改为核对清单及时间点。
- 尊重减少动态效果设置；关闭动态时仍显示正确代表图。
- 不改变用户选择的人物大小、额度大小及持久化设置。
- 60 FPS 是动画素材采样目标，实际显示还受刷新率、解码和设备性能影响。不得仅看计时器配置就宣称显示达到 60 FPS。

## 验收与交付

```powershell
.\.venv-interpolation\Scripts\python.exe scripts/frame-rate-job.py validate --job artifacts/frame-rate-60 --output artifacts/frame-rate-60/output
npm ci
npm test
npm run smoke:animation
```

结构检查器只验证清单、帧数、尺寸、Alpha 和时间配置，不能证明插值质量或真实播放帧率，仍需：

- 检查全部 16 组的首尾循环接缝，非循环末帧及总时长。
- 抽查运动段新增帧不是复制，检查透明边缘和形变；保存逐帧对照。
- 在真实 Electron 窗口记录至少 60 秒的实际呈现间隔、掉帧比例、CPU、内存；测试 100%/150% 人物尺寸及切换动作。
- 5080 只负责离线生成；运行桌宠不得依赖 CUDA、Python 或下载模型。Mac/Windows/Linux 共用生成后的素材。
- 全部通过后备份正式 assets，再替换素材与 manifest。提交生成脚本、模型出处及许可说明、播放器改动、结果清单和测试报告。
- Windows 先实机验证；Mac/Linux 没有实机时明确标记，不能写“三端实测通过”。依赖现有 CI 做三端打包验证。
- 输出压缩包包括 `output/assets/`、脚本、manifest、模型哈希与报告；不含模型、.venv、API Key、Codex 用户数据。
- 将更新提交到本仓库的工作分支并推送，交付准确 commit hash；不要自动创建重复仓库或发布 Release。

完成后向用户报告：实际帧数、时长偏差、帧率表现、素材体积、处理耗时及限制。若 GPU、透明通道或视觉质量未通过，报告具体问题并保留 1.9.7 正式素材，不得宣称已经升级到 60 FPS。
