# RTX 5080：全量动画 4 倍超分与 60 FPS 交接任务书

## 目标与优先级

为 Codex Whale Girl 准备完整高清动画库：**上游全部 106 个透明动画 + 现用 16 组原始帧**，从原始分辨率做宽高各 4 倍的 AI 超分，并把运动动画补到 60 FPS。原作者动作名称、描述、时间段、分类和许可随素材保留。完成后把所有合格动作接入现有桌宠的动作目录；现有 Codex 工作状态、用量牌和交互保持可用。

本任务书替代旧的“仅 16 组/2 倍/6 个新增动作”范围。包内是**输入素材和项目快照**，尚未执行本轮 4 倍超分或补帧。旧的 2 倍高清资源仅作对照。模型、GPU 环境和 RGBA 补帧适配器需要执行代理在家里的 Windows / RTX 5080 上安装、实现和验证，不是已经完成的一键 GPU 成品。

## 一、打开交接包

1. 解压到较短路径，如 `D:\WhaleJob`，避免 Windows 深层中文路径过长。
2. 阅读根目录 `START-HERE.md`；用 Chrome / Edge 打开 `动作目录.html`，可以按作者原名或分类搜索、播放源动画、查看作者完整动作说明。
3. 执行 `py -3 verify-inputs.py`。它只校验包内文件 SHA256，不安装软件、不运行模型。必须全通过再处理。
4. `inventory.json` 是输入清单和处理目标；`checksums.json` 是整包文件校验表；`provenance.json` 记录两个项目快照、历史原始帧提交和来源许可。

| 路径 | 内容及用途 |
| --- | --- |
| `upstream/` | PC2005-cloud/dsh-pet 固定提交的完整源码和素材；包含 106 个透明 WebM、106 个 GIF 预览、作者提示词全文、动作配置、许可 |
| `original-frames/` | 当前桌宠 16 组共 2,600 张超分前原始透明 WebP，412×344 |
| `original-manifest.json` | 原始帧顺序、42ms 时长、循环和 Codex 动作映射 |
| `project/` | Codex Whale Girl 已提交的完整项目快照，含目前 2 倍素材、源码、测试和锁文件；无 Git 历史和依赖目录 |
| `author-descriptions/` | 从作者动作提示词按原名精确匹配的 106 段原文，包含按秒动作说明；未把我们的建议混入作者文字 |
| `任务书.md` | 本文 |

上游提交固定为 `631c5310b047931404978152fdc7865413c153ec`。上游提示词描述的是原作者制作意图，可能与成片有差异；**只把它当动作说明和验收参考，不能把其中“生成绿幕”等文字作为本次重新生成视频的指令**。本次只增强已存在的透明动画。

上游 106 段与现用 16 组存在重合/派生关系，共 122 个输入处理条目，不代表 122 个互不相同的新动作。先全部处理留档，再以人工确认的映射去重展示，不能仅凭相似文件名删除原始条目。

## 二、明确输出尺寸与帧率

- 106 段上游 WebM：按各自探测的源尺寸宽高 ×4；当前 640×360 的目标为 **2560×1440、60 FPS、透明背景**。真实参数见 inventory，不把所有片段强制当作 10 秒。
- 16 组现用帧：412×344 → **1648×1376、60 FPS、RGBA**。直接用 original-frames；不能把 project 内 824×688 的 2 倍图再放大 4 倍，也不串行做两轮 2 倍冒充直接 4 倍。
- `dragging_dizzy` 是单帧静态姿势，只做 4 倍超分，保持一帧，不复制成 60 帧。
- “4 倍”指宽高均 ×4、像素数 ×16。保留画布比例、透明留白、人物位置及脚底锚点，不能把两种画布拉伸成同一个比例。
- 动作时间保持原速；目标采样时刻 `k/60` 秒。读取真实 PTS 和时长，不能只修改 FPS 标签、加速播放或复制原帧假装补帧。
- 可额外提供 30 FPS 或 2 倍的低负载播放版本，但必须同时交付完整 4 倍 / 60 FPS 主版本，不得悄悄降级。
- 不自动增加对比度、锐化或人脸修复；先沿用用户已认可的 AnimeVideo 风格。若做对比增强，单独输出样片和参数，不覆盖无增强主版本。

## 三、环境与模型

使用独立 Python 环境、官方模型与可信 FFmpeg 构建。先确认 `nvidia-smi` 识别 RTX 5080，安装支持该 GPU 的 PyTorch CUDA 构建，并实际跑 GPU 矩阵计算；仅 `cuda.is_available()` 为真不算验证完成。

- 超分优先评估 Real-ESRGAN **AnimeVideo-v3 的 4 倍模型/配置**；官方 Python 和 NCNN 路线任选，确认实际模型倍率和输出尺寸。不要把原 Mac 的 arm64 二进制拿到 Windows 执行。
- 补帧评估 Practical-RIFE 官方动画适用模型；按所选提交实际接口实现任意时刻插值与 RGBA 处理。记录仓库提交、模型文件 SHA256、推理精度、分块参数、软件及驱动版本。
- 先 FP32 确认质量，再评估 FP16 和分块。优先比较“源分辨率补帧后 4 倍超分”和“4 倍超分后补帧”两条路线，用透明边缘、时序闪烁、耗时和显存实测选型。
- 包内不附模型权重、CUDA、FFmpeg、Python 或 npm 依赖；首次准备环境需要联网。不要索取 Codex 登录文件、API Key 或对话数据。

官方入口：

- https://github.com/xinntao/Real-ESRGAN
- https://github.com/xinntao/Real-ESRGAN-ncnn-vulkan
- https://github.com/hzwer/Practical-RIFE
- https://pytorch.org/get-started/locally/
- https://ffmpeg.org/download.html

## 四、透明解码与补帧

1. WebM 是 VP9 Alpha。FFmpeg 默认解码器可能只给 RGB/YUV 而丢 Alpha；使用支持 Alpha 的 `libvpx-vp9` 解码，并对实际解码后的 RGBA 检查透明像素、半透明边缘和不透明主体。`alpha_mode=1` 元数据本身不能证明解码成功。
2. 可先用 `ffmpeg -c:v libvpx-vp9 -i input.webm -frames:v 1 -pix_fmt rgba sample.png` 验证。路径通过参数数组传递，不拼接未经转义的作者文件名。
3. 保留源 PTS；超分 RGB 的同时妥善处理 Alpha。纯空间缩放 Alpha 可用经过验证的高质量滤波；运动补帧必须让 Alpha 随同一运动场和遮挡权重变化，不能简单把相邻 Alpha 平均。
4. 阅读所选 RIFE 实现，取得对应时间的双向 flow / mask 或实现可验证的替代方法。不能假设普通 RGB RIFE 已原生支持 RGBA，也不能从补帧后的黑底图重新抠图。
5. 正确处理预乘/非预乘 Alpha、边缘颜色延展、裁切和填充；黑、白、灰与棋盘格背景都不得出现黑边、白边、双影和透明孔洞漂移。
6. 循环片段检查末帧→首帧；非循环片段保持末姿势，不跨到别的动作。上游提示词“最后回到起始姿态”不等于成片必然无缝，要逐段检验；如需修缝，记录具体处理而不修改原文件。

## 五、先测样片，再跑完整队列

先选现用 working（很多工具）、working_command（翻任务单）、thinking、dragging，以及上游三球抛接、荡秋千、文字动作和带气泡动作。每段抽 2 秒，并额外检查循环接缝。

提供同尺寸同步对比页：原始、当前 2 倍（若有）、4 倍原帧率、4 倍 60 FPS。支持暂停、逐帧、背景切换，检查眼睛、手指、工具、细发丝、文字、鲸鱼尾巴和半透明特效。

样片通过后全量执行所有 inventory 条目。脚本必须支持：按动作选择、断点续跑、原文件只读、原子输出、失败重试及日志。缓存键绑定源 SHA256、模型 SHA256、倍率、帧率和全部参数；失败片段不得标成完成。

按样片测量估算时长和空间。106 段大多约 10 秒，但必须用清单精确求和；临时 PNG 可能占用数百 GB。分段生成、验收、编码，验证最终文件可解码后才清理可重建中间文件，避免一次展开全库。不要预报未经测量的 5080 耗时。

## 六、输出和桌宠接入约定

交付目录：

```text
output/
  upstream-4x60/<稳定ID>/animation.webm
  upstream-4x60/<稳定ID>/poster.png
  current-4x60/<原clip名>/...webp
  actions.json
  dsh-pet-manifest.json
  processing-report.json
  comparison.html
  scripts/
  licenses/
```

- 上游动画优先 VP9 Alpha WebM，保持透明；不要用普通 MP4 作为交付。逐段记录实际编码参数、Alpha 解码结果、尺寸、帧数、PTS、时长和哈希。海报取有代表性的时间点，保留作者动作原名。
- 当前 16 组可以先按上述 WebP 清单交付，以便现播放器接入。若统一改透明视频，必须完整更新状态切换、非循环结束回调、拖动、摸头、代表图等行为并验证后再替换。
- `actions.json` 每项包含稳定 ID、作者原名、原文描述路径、作者分类、来源提交/路径/哈希、输出路径/哈希、宽高/FPS/帧数/时长、loop、noMirror、海报时间、角色脚底锚点、适用场景。作者分类与本项目 Codex 映射分开存放。
- 上游原始 config.jsonc 的分类、事件档位、移动参数和 noMirror 随包保留。文字类禁止镜像；移动/转向动作有位移和朝向语义，不能无条件当作普通待机随机播放。余额事件的“已用百分比”与当前用量牌的“剩余百分比”必须明确换算。
- 全部合格动作放进现有“更多动作”的分类/搜索目录；工作、等待、额度事件类保留手动预览入口，自动触发由相应 Codex 事件控制。不要让错误/庆祝/余额动画在普通待机时误触发。
- 保持已确认的对应：查找资料→翻任务单，运行/修改/测试→工具环绕；左右观察用于等待/观察，不能替代查找资料。采用作者描述帮助匹配，但实际画面必须复核。
- 工作气泡继续使用“查找资料中 / 工作中 / 遇到问题了”等自然文字。保留持久额度、点击空白收起详情、人物与额度独立缩放、深浅色气泡和拖动锚点。
- 大素材只加载当前动作与有限预加载，不能一次解码全库。4 倍帧的像素缓存要重新计算，旧的 2 倍缓存估算不可沿用；必要时提供可选轻量播放档，高清母版仍完整保留。
- WebP 播放器应改为基于真实时间的 requestAnimationFrame 调度，避免计时器拖慢动作；视频播放器在切换时清理旧播放和异步回调。代表图按时间选择，不能沿用硬编码帧序号。

## 七、验收与带回来的东西

- inventory 的 106 个上游动作与 16 组现用帧逐项有 completed / failed 结果；失败必须保留输入并写原因，不可漏项。单帧静态例外记录清楚。
- 运动输出真实 60 FPS，尺寸为源宽高 ×4；时长偏差原则上不超过一个目标帧。检查整个序列，而非只看文件头或计时器。
- 验证新增帧确实插值、运动自然，检查所有动作接缝及 Alpha。对比源帧抽查，不能把帧复制/混合当作 AI 补帧。
- 在 Electron 实机记录至少 60 秒的帧呈现间隔、掉帧比例、CPU、内存，分别测试人物 100% / 150%、用量牌最大尺寸、频繁切换、拖动和工作状态恢复。
- 项目执行 `npm ci`、`npm test`、`npm run smoke:animation` 和三端构建检查。Windows 做实机；Mac/Linux 未实机的必须明确标记。
- 旧 `scripts/frame-rate-job.py` 只针对 16 组且校验尺寸固定为 824×688，**不能直接作为本任务验收器**。应扩展为读取本次输入清单、源 PTS 和 4 倍尺寸；保留已有时间轴测试，并覆盖不同画布、106 段视频、单帧例外和循环。
- 带回完整输出素材、结果清单、可复现推理/编码脚本、所用模型下载地址与 SHA256、对比页和测试报告。模型如另行携带，单独放工具包并保留许可，不加入桌宠安装包。
- 桌宠运行不依赖 CUDA / Python / 模型，三个平台共用离线生成素材。不要自动创建新仓库、发布 Release 或把大体积母版直接塞进 Git 历史；先报告体积并给出安装包与资源包方案。
- 当前交接包里的 project 没有 `.git`。联网时克隆现有仓库并核对 provenance 中的快照提交，再带回改动；离线可直接以快照开发，交付源码差异清单和补丁。保留所有既有来源及许可。
